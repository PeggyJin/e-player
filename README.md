# NISSAN E級玩家｜駕馭新動力，E起淨海趣！
## 活動網頁：部署與測試教學

這份教學分成五個部分，照順序做即可，**不需要寫程式**。總時間約 40～60 分鐘。

1. 認識檔案（2 分鐘）
2. 設定雲端上傳：Google Apps Script（15 分鐘）
3. 把網頁放上網路：GitHub Pages（15 分鐘）
4. 產生並列印 QR code（5 分鐘）
5. 測試與活動前檢查

---

## 第一部分：認識檔案

```
e-player/
├─ index.html        工作人員入口（三隊連結、測試模式、QR code）
├─ yellow.html       閃電E隊（黃）← QR code 指向這裡
├─ red.html          活力E隊（紅）
├─ green.html        生態E隊（綠）
├─ qrcodes.html      三隊 QR code 列印頁
├─ config.js         ★ 設定檔：要改的東西都在這裡
├─ README.md         本教學
├─ assets/           共用的程式、樣式、圖片（一般不用動）
│   ├─ app.js        主程式（三隊共用）
│   ├─ app.css       樣式（三隊共用）
│   ├─ pixel.js      像素圖案
│   ├─ kv.webp       活動主視覺
│   ├─ nissan-logo.png
│   └─ vendor/qrcode.js
└─ apps-script/Code.gs   雲端上傳後端（貼到 Google Apps Script 用）
```

**三隊共用同一套程式。** `yellow.html`／`red.html`／`green.html` 只寫了「我是哪一隊」，畫面與功能都來自 `assets/` 裡的共用檔，所以改一次，三隊都會套用。

### config.js 裡可以改的設定

| 設定 | 說明 | 預設 |
|---|---|---|
| `STAFF_CODE` | 工作人員通關碼（人工放行、重設進度都用這組） | `'1205'` **← 活動前請改掉** |
| `UPLOAD_URL` | Apps Script 網址（第二部分會拿到） | 空白＝不上傳 |
| `VIDEO_MAX_SECONDS` | 濾鏡錄影最長秒數 | 15 |
| `VIDEO_WITH_AUDIO` | 錄影是否收音 | true |
| `SOUND` / `VIBRATE` | 成功音效、震動 | true |
| `COLOR_RULES.MIN_RATIO` | 顏色辨識門檻（框內符合顏色的比例） | 0.12（12%） |
| `TEAMS` | 各隊隊名、顏色、文字、網址 | — |
| `TEXT` | 任務說明、完成頁文字 | — |
| `EVENT_DATE_TEXT` / `EVENT_PLACE_TEXT` | 濾鏡上的日期與地點 | 2026.12.05／台中大甲 |

修改時只改**引號裡面**的內容，引號和行尾的逗號都要保留。

## 第二部分：設定雲端上傳（Google Apps Script）

完成後，參加者拍的任務照片會存進你的 Google 雲端硬碟（依隊伍分成三個資料夾），每一張也會在 Google 試算表留下一筆紀錄。

### 步驟 1：建立試算表
1. 打開 <https://sheets.google.com>，用**你要存照片的 Google 帳號**登入。
2. 點「空白試算表」，把左上角的檔名改成 `E級玩家淨灘上傳紀錄`。

### 步驟 2：貼上程式
1. 在試算表上方選單點 **擴充功能 → Apps Script**，會開啟新分頁。
2. 左上角的「未命名的專案」可以改名為 `E級玩家上傳`。
3. 編輯區裡預設有一段 `function myFunction() {...}`，**全部刪掉**。
4. 用記事本（Windows）或文字編輯（Mac）打開 `apps-script/Code.gs`，全選複製，貼到編輯區。
5. 按上方的 **💾 儲存** 圖示。

### 步驟 3：執行一次「setup」並授權
1. 上方工具列「▶ 執行」旁邊有一個函式選單，選 **`setup`**。
2. 按 **▶ 執行**。
3. 出現「需要授權」→ 按 **審查權限** → 選你的帳號。
4. 出現「Google 尚未驗證這個應用程式」時，點左下角 **進階** → **前往「E級玩家上傳」（不安全）**。
   （這是你自己寫的程式，所以 Google 會這樣提示，可以放心。）
5. 按 **允許**。
6. 下方「執行紀錄」出現 `設定完成！` 就成功了。回到雲端硬碟，會看到 `E級玩家淨灘_任務照片` 資料夾，裡面有三隊的子資料夾。試算表也會多一個「上傳紀錄」工作表。

### 步驟 4：部署成網頁應用程式
1. 右上角按 **部署 → 新增部署作業**。
2. 點「選取類型」旁的 ⚙ 齒輪 → 選 **網頁應用程式**。
3. 依序設定：
   - 說明：`E級玩家上傳 v1`
   - 執行身分：**我**（你的 Email）
   - 誰可以存取：**所有人** ← 很重要，參加者不用登入 Google 才能上傳
4. 按 **部署**，有出現授權畫面就再允許一次。
5. 複製 **網頁應用程式網址**（`https://script.google.com/macros/s/……/exec`），先存在記事本。

### 步驟 5：確認部署成功
把剛剛的網址貼到瀏覽器打開，看到這段文字就表示成功：
```
{"ok":true,"message":"E級玩家上傳服務運作中"}
```

> **如果之後修改了 Code.gs：** 修改完要到 **部署 → 管理部署作業 → ✏️ 編輯 → 版本選「新版本」→ 部署**。網址不會變，但不做這一步，修改不會生效。

## 第三部分：把網頁放上網路（GitHub Pages，免費）

### 步驟 1：建立 GitHub 帳號與專案
1. 到 <https://github.com> 註冊並登入。
2. 右上角 **＋ → New repository**。
3. Repository name 填 `e-player`（之後網址會用到），選 **Public**，按 **Create repository**。

### 步驟 2：上傳檔案
1. 在新專案頁面點 **uploading an existing file** 連結。
2. 把解壓縮後 `e-player` 資料夾**裡面的所有東西**（`assets` 和 `apps-script` 資料夾、所有 .html、config.js、README.md）一起拖進網頁。
   - 要拖的是資料夾「裡面」的內容，不是 `e-player` 資料夾本身。
   - 建議用電腦版 **Chrome** 拖曳，才能一次上傳整個資料夾。
3. 等檔案列表都出現後，按最下方綠色 **Commit changes**。

### 步驟 3：開啟 GitHub Pages
1. 專案頁上方點 **Settings** → 左側選 **Pages**。
2. Source 選 **Deploy from a branch**，Branch 選 **main**、資料夾選 **/ (root)**，按 **Save**。
3. 等 1～3 分鐘後重新整理頁面，上方會出現網址：`https://你的帳號.github.io/e-player/`

各頁網址：
- 黃隊：`https://你的帳號.github.io/e-player/yellow.html`
- 紅隊：`https://你的帳號.github.io/e-player/red.html`
- 綠隊：`https://你的帳號.github.io/e-player/green.html`
- 工作人員入口：`https://你的帳號.github.io/e-player/`

### 步驟 4：填入上傳網址與通關碼
1. 在 GitHub 專案頁點 `config.js` → 右上角 **✏️（Edit this file）**。
2. 把第二部分拿到的網址貼到 `UPLOAD_URL: ''` 的引號裡：
   ```js
   UPLOAD_URL: 'https://script.google.com/macros/s/xxxxxxxx/exec',
   ```
3. 把 `STAFF_CODE` 改成你們的通關碼，例如 `'8642'`。
4. 按 **Commit changes**。

> **修改後多久生效？** GitHub Pages 約 1～10 分鐘更新。手機如果還看到舊版，可以在網址後面加 `?v=2`（每次換個數字）強制重新讀取，或等 10 分鐘。

## 第四部分：產生並列印 QR code

1. 用電腦打開 `https://你的帳號.github.io/e-player/qrcodes.html`。
2. 頁面會**自動依目前網址**產生三隊 QR code（也可以在 config.js 的 `TEAMS → url` 手動填網址）。
3. 上方按鈕可以切換「三隊一頁」或「每隊一頁（大張）」，再按 **🖨 列印**。
4. **列印前，先用 iPhone 和 Android 各掃一次**，確認會進到正確隊伍。

> QR code 的網址結尾會自動加上 `?openExternalBrowser=1`：參加者用 LINE 掃描時，會自動改用 Safari／Chrome 開啟（LINE 內建瀏覽器常常打不開相機）。這不影響其他掃描方式。

## 第五部分：測試

### A. 用電腦測試（Chrome，需要網路攝影機）
1. 打開 `https://你的帳號.github.io/e-player/`（工作人員入口），點「測試模式」的任一隊。
2. 測試模式會多出兩樣東西：
   - 拍照結果會顯示「符合比例 xx%（門檻 12%）」，方便調整門檻
   - 相機畫面下方有「（測試）從相簿選圖」，可以直接選電腦裡的照片來測辨識
3. 想看手機版面：按 `F12` → 左上角手機圖示 → 選 iPhone 12 Pro 之類的機型。

### B. 用手機測試（iPhone Safari、Android Chrome 各一支）
請各跑一次完整流程，逐項打勾：

- [ ] 掃 QR code 直接進入正確隊伍頁，主視覺、隊名、隊色都正確
- [ ] 按「開始任務」→ 允許相機 → 開的是**後鏡頭**
- [ ] 拍隊伍顏色的物品 → 成功、電量條亮一格、有音效（iPhone 要關掉靜音開關）
- [ ] 拍其他顏色 → 失敗；同一格失敗 2 次後出現「請工作人員協助」
- [ ] 輸入錯的通關碼會晃動，輸入正確的會放行
- [ ] 關掉網頁再打開，進度還在
- [ ] 3 格完成 → 充電動畫 → 濾鏡相機
- [ ] 濾鏡：前後鏡頭切換、拍照、錄影（15 秒會自動停止）
- [ ] 預覽 → 儲存：
  - iPhone：跳出分享選單 → 點「儲存影像」／「儲存影片」→ 到照片 App 確認
  - Android：直接下載 → 到相簿或「下載」資料夾確認
- [ ] 完成頁文字正確
- [ ] 雲端硬碟對應的隊伍資料夾出現照片；試算表多了紀錄（人工放行那張標示「是」）
- [ ] 斷網測試：開飛航模式拍一張成功照片 → 首頁顯示「1 張照片等待上傳」→ 關閉飛航模式，約 20 秒內自動補傳

### C. 測試完：清除測試資料
- **手機進度**：在首頁**長按最下方 NISSAN logo 約 3 秒** → 輸入通關碼 → 確定重設。
- **雲端資料**：刪除試算表裡的測試列，以及雲端硬碟資料夾裡的測試照片。

### D. 活動前檢查清單
- [ ] `STAFF_CODE` 已經改掉，所有工作人員都知道
- [ ] `UPLOAD_URL` 已經填好，用手機測過上傳
- [ ] 帶三種顏色的實際海廢（或類似物品）**到戶外陽光下**測試，看符合比例是否穩定高於門檻
- [ ] QR code 已列印，並註明「請用 Safari／Chrome 開啟」
- [ ] 工作人員知道：①失敗 2 次會出現協助按鈕 ②長按 logo 可以重設進度
- [ ] 可以的話，先確認活動海灘的手機網路訊號

## 調整與疑難排解

### 現場太難過關或太容易過關
打開 `config.js`，修改 `COLOR_RULES` 裡的 `MIN_RATIO`：
- 太難過關（真的是該顏色卻一直失敗）→ 調低，例如 `0.08`
- 太容易過關（別的顏色也會成功）→ 調高，例如 `0.18`

建議用「測試模式」實拍幾次，看符合比例大多落在多少，再決定數字。各色的色相範圍（`hue`）和飽和度（`sMin`）也可以微調，檔案裡有註解說明。

### 相機打不開
- **在 LINE／Facebook／Instagram 裡開啟：** 畫面會提示改用瀏覽器開啟。LINE 掃描本活動 QR code 時會自動跳轉。
- **權限被拒絕：**
  - iPhone：點網址列左邊「ᴀA」→ 網站設定 → 相機 → 允許
  - Android：點網址列左邊的圖示 → 權限 → 相機
- **都不行時：** 錯誤畫面有「📷 改用手機相機拍照」按鈕，會改用手機內建相機拍照，一樣可以辨識和上傳。

### 照片沒有上傳
1. 確認 `config.js` 的 `UPLOAD_URL` 正確，結尾是 `/exec`。
2. 用瀏覽器打開該網址，確認看到 `"ok":true`。
3. 確認 Apps Script 部署時「誰可以存取」選的是**所有人**。
4. 如果改過 Code.gs，記得「管理部署作業 → 編輯 → 新版本」。
5. 照片在上傳成功前都存在手機裡，網路恢復或下次打開網頁時會自動補傳。

### iPhone 沒有音效
iPhone 側邊的靜音開關打開時，網頁不會發出聲音，這是 iPhone 的限制。

### Android 錄影存成 .webm
少數較舊的 Android 瀏覽器只能錄 WebM 格式。大多數相簿 App 都能播放；新版 Chrome 會存成 MP4。

### 安全性說明
網頁原始碼是公開的，懂技術的人可以在 `config.js` 看到通關碼和上傳網址。以一般活動來說風險很低；如果擔心，可以活動當天早上再換一組新的通關碼。
